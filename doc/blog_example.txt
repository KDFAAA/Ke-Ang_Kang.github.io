                <p>本文记录了我在忘记 VMware Workstation 虚拟机加密密码后，通过 PowerShell 调用 Windows 凭据管理器 API 成功恢复密码的完整过程。如果你也遇到了同样的问题，希望这篇文章能帮到你。
                <h2 id=起因>
                    <a class=headerlink href=#起因 title=起因></a>
                    起因
                </h2>
                <p>前几天我需要迁移一台之前创建的 VMware 加密虚拟机，选择导出 OVF，结果弹出了密码输入框 —— 我完全不记得当时设置了什么密码。
                <p>说实话，这个密码根本不是我主动设置的。VMware Workstation 在某些操作（比如启用加密、克隆加密虚拟机）时会引导你设置加密密码，同时提供一个「Remember the password」（记住密码）选项。当时我随手勾选了这个选项，之后每次打开虚拟机都是自动解锁的。
                <p>直到需要迁移虚拟机时，它需要用户主动输入密码了。于是我开始研究恢复方案。
                <h2 id=原理>
                    <a class=headerlink href=#原理 title=原理></a>
                    原理
                </h2>
                <p>经过一番搜索，我了解到以下关键信息：
                <ol>
                    <li>
                        VMware Workstation 在你勾选「Remember the password」时，会将加密密码存储在 <strong>Windows 凭据管理器（Credential Manager）</strong>
                        中。
                    <li>
                        每台加密虚拟机都有一个唯一的 <strong>GUID</strong>
                        ，VMware 用这个 GUID 作为凭据的名称（Target Name）来存储密码。
                    <li>
                        虽然你可以在 Windows 的「凭据管理器」界面中看到这些条目，但<strong>界面上不会显示密码明文</strong>
                        。
                    <li>
                        好消息是，我们可以通过 Windows 的 
                        <strong>
                            Win32 <code>CredReadW</code>
                            API
                        </strong>
                        直接读取凭据中存储的密码。
                </ol>
                <p>换句话说，密码一直都在你的电脑里，只是 VMware 没有提供一个「显示密码」的按钮而已。
                <h2 id=恢复步骤>
                    <a class=headerlink href=#恢复步骤 title=恢复步骤></a>
                    恢复步骤
                </h2>
                <h3 id=找到虚拟机的加密-GUID>
                    <a title="找到虚拟机的加密 GUID" class=headerlink href=#找到虚拟机的加密-GUID></a>

                </h3>
                <p>

                <p>
                    在五年前的文章<a href=/2021-07/%E5%B0%86Yeelight%E7%83%9B%E5%85%89%E6%B0%9B%E5%9B%B4%E7%81%AF%E6%8E%A5%E5%85%A5Apple%20HomeKit/>将 Yeelight 烛光氛围灯接入 Apple HomeKit</a>
                    中，笔者介绍了通过 Homebridge 控制 Yeelight 烛光氛围灯的方法。然而，笔者在将 Homebridge 相关代码迁移（使用 AI 转写）到 ESPHome 平台，并尝试在 Home Assistant 中使用时，发现原版代码的蓝牙交互实际上存在问题。<a href=https://github.com/stevenjoezhang/homebridge_yeelight/blob/adad612ec84bfc82a18105b551b1fd7a2ded5f1f/yeelight/lib/yee.js#L549-L556 rel=noopener target=_blank>yee.js</a>
                    使用了<code>0x43,0x67,0xde,0xad,0xbe,0xbf</code>
                    作为蓝牙连接后认证的 payload，但这实际上无效；即使 ESP32 和灯连接上了蓝牙，过一段时间后就会断开，下次控制时又需要重新连接。
                <p>
                    经过搜索，笔者找到了两个重要的参考：<a href=https://github.com/esphome/feature-requests/issues/674 rel=noopener target=_blank>I need Help to use esp32 to Control Yeelight Candla BLE Lamp with MQTT / HomeAssisant</a>
                    以及<a href=https://sspai.com/post/76147 rel=noopener target=_blank>“失联” 7 年的 Yeelight 烛光氛围灯，上线 HomeKit 平台 | 新人报到 - 少数派</a>
                    。根据这些资料，如果不完成配对，蓝牙每过一段时间就会被强制断开，和笔者遇到的情况一致。而测试成功的交互流程是，连接蓝牙后发送<code>0x43,0x40,0x02</code>
                    进行认证，此时灯会进入配对模式，亮度会闪烁，之后旋转氛围灯，就可以配对成功。

                <p>
                    笔者做的主要更改是支持了<code>sensor_yeelight_notify</code>
                    ，它监听灯的状态变化，并将状态同步到 ESPHome 的 light 实体上。这样，无论是通过 Home Assistant 控制灯，还是直接旋转灯进行亮度调节，ESPHome 都能正确地获取灯的状态并更新。
                <p>使用方式是：
                <ol>
                    <li>
                        将上述代码保存为<code>yeelight.yaml</code>
                        ，并替换其中的<code>YEELIGHT_MAC</code>
                        为实际的灯的 MAC 地址（可以先扫描附近的 BLE 设备，然后根据名称<code>yeelight_ms</code>
                        或者<code>yl_candela</code>
                        找到灯），配对按键使用的<code>GPIO0</code>
                        也可以根据情况修改。
                    <li>
                        通过<code>esphome run yeelight.yaml</code>
                        将代码烧录到 ESP32 上。
                    <li>确保灯处于蓝牙连接范围内。
                    <li>
                        通过<code>esphome logs yeelight.yaml</code>
                        查看日志，在配对成功前，可以看到 ESP32 和灯的蓝牙连接间歇性断开，虽然 ESP32 会自动重连，但是此时操作的延迟会很大。
                    <li>
                        趁着连接成功的间隙，按下配对按钮（这里使用的是<code>GPIO0</code>
                        ，通常是 ESP32 开发板的<code>BOOT</code>
                        按钮），等待 ESP32 开发板上的 LED 亮起，氛围灯也开始闪烁时，表示开始配对，此时旋转灯进行配对。
                    <li>配对成功后，ESP32 和灯的连接会保持稳定，此时就可以添加进 Home Assistant，来控制灯的开关和亮度了。
                </ol>

                <p>
                    在文章<a href=/2023-02/%E5%B0%86%E5%85%AC%E7%89%9B%E6%99%BA%E5%AE%B6%E8%AE%BE%E5%A4%87%E6%8E%A5%E5%85%A5Home%20Assistant/>将公牛智家设备接入 Home Assistant</a>
                    中，笔者介绍了通过抓包分析将公牛智能开关接入 Home Assistant 的方法。最近，家里的菲斯曼（Viessmann）壁炉也需要接入智能家居系统，以便更灵活地控制暖气和热水温度。虽然菲斯曼官方提供了 ViCare App，但其对第三方集成的支持主要集中在欧洲服务器，而中国区的设备使用的是独立的服务器和 API，现有的开源插件无法直接使用。因此，笔者再次通过抓包分析，实现了对菲斯曼中国区设备的接入。
                <p>经过分析，菲斯曼中国区 API 主要包括以下几个部分：
                <ul>
                    <li>
                        <code>/idass/user/login</code>
                        ，提交手机号和密码进行登录，获取<code>access_token</code>
                        。
                    <li>
                        <code>/api/home/familyDevices/v2</code>
                        ，获取家庭设备列表，包括壁炉的<code>physicsId</code>
                        等关键信息。
                    <li>
                        <code>/api/device/detail</code>
                        ，获取设备的详细运行状态，如当前模式、故障代码等。
                    <li>
                        <code>/api/device/scanStatus</code>
                        ，获取设备的实时传感器数据，如出水温度、燃烧状态等。
                    <li>
                        <code>/api/3/sendToDevice/setChsetTemp</code>
                        等控制接口，用于设置暖气温度、热水温度和运行模式。
                </ul>
                <p>通过这些 API，我们可以在 Home Assistant 中实现以下功能：
                <ol>
                    <li>
                        <strong>暖气控制</strong>
                        ：调节暖气目标温度，切换制热 / 防冻模式。
                    <li>
                        <strong>热水控制</strong>
                        ：调节生活热水目标温度。
                    <li>
                        <strong>状态监测</strong>
                        ：实时查看壁炉是否在燃烧、出水温度以及是否有故障报警。
                </ol>
                <p>
                    全部代码已开源至<a href=https://github.com/stevenjoezhang/hass-viessmann-cn rel=noopener target=_blank>hass-viessmann-cn</a>
                    ，可以直接在 Home Assistant 中使用。安装方法非常简单，支持 HACS 一键安装，配置时只需输入菲斯曼 App 的账号密码即可。
            </div>

                <p>
                    笔者有一台小爱音箱，可惜它并不支持 AirPlay 协议。如果要将 Mac 上的音乐串流到这台音箱上播放，就需要通过蓝牙配对，体验并不理想。幸运的是，这个型号的音箱配备了 USB 接口，并且可以通过 USB 声卡的方式被电脑识别为音频输出设备。这就意味着，可以通过 Shairport Sync 等软件进行 AirPlay 协议配对，然后通过 USB 将音频流发送到这台音箱上播放。<br>
                    这台音箱摆放位置旁边就是 NAS 服务器，运行着 TrueNAS Scale 25.04 系统。直接在 NAS 服务器上安装 Shairport Sync 并连接音箱是一个不错的选择。这个版本的 TrueNAS 支持运行 Docker 容器，因此软件安装上非常方便，不过在调试过程中还是踩了很多坑。本文记录一下安装过程，供参考。

            <div class=post-body itemprop=articleBody>
                <p>在 Ubuntu 系统上，有时我们需要对某些内核模块进行定制化修改，例如更新补丁、进行调试或加入额外日志等。完整重新编译内核会非常耗时，但好消息是：Linux 的内核构建系统允许我们仅重新编译目标模块，而不需要构建整个内核。
                <p>
                    本文介绍如何在 Ubuntu 上为当前正在运行的内核版本重新编译一个模块，并正确安装和加载它。示例模块为 <code>kvm-intel.ko</code>
                    。
                <h2 id=准备内核源码>
                    <a class=headerlink href=#准备内核源码 title=准备内核源码></a>
                    准备内核源码
                </h2>
                <p>
                    Ubuntu 提供了与当前内核版本在同一 ABI 下的源码，可以通过 <code>apt-get</code>
                    直接获取：
                    <figure class="highlight sh">
                        <table>
                            <tbody>
                                <tr>
                                    <td class=gutter>
                                        <pre>
                                            <span class=line>1</span>
                                            <br>
                                        </pre>
                                    <td class=code>
                                        <pre>
                                            <span class=line>
                                                apt-get <span class=built_in>source</span>
                                                linux-image-unsigned-$(<span class=built_in>uname</span>
                                                -r)
                                            </span>
                                            <br>
                                        </pre>
                        </table>
                    </figure>
                <p>
                    执行后目录中通常会出现类似：
                    <figure class="highlight plaintext">
                        <table>
                            <tbody>
                                <tr>
                                    <td class=gutter>
                                        <pre>
                                            <span class=line>1</span>
                                            <br>
                                        </pre>
                                    <td class=code>
                                        <pre>
                                            <span class=line>linux-hwe-6.8-6.8.0/</span>
                                            <br>
                                        </pre>
                        </table>
                    </figure>
                <p>这就是 Ubuntu 为 HWE 6.8 系列内核提供的完整源码树。
                <h2 id=同步配置与符号信息>
                    <a class=headerlink href=#同步配置与符号信息 title=同步配置与符号信息></a>
                    同步配置与符号信息
                </h2>
                <p>Kernel module 的编译依赖两个关键文件：
                <ol>
                    <li>
                        <code>.config</code>
                        — 当前内核的编译配置
                    <li>
                        <code>Module.symvers</code>
                        — 内核导出的符号版本信息
                </ol>
                <p>这两者必须与正在运行的内核一致，否则编译出的模块会因为 ABI 不一致而无法加载。
                <p>
                    我们将系统中的配置和符号文件复制到源码树中：
                    <figure class="highlight sh">
                        <table>
                            <tbody>
                                <tr>
                                    <td class=gutter>
                                        <pre>
                                            <span class=line>1</span>
                                            <br>
                                            <span class=line>2</span>
                                            <br>
                                        </pre>
                                    <td class=code>
                                        <pre>
                                            <span class=line>
                                                <span class=built_in>cp</span>
                                                /boot/config-$(<span class=built_in>uname</span>
                                                -r) .config
                                            </span>
                                            <br>
                                            <span class=line>
                                                <span class=built_in>cp</span>
                                                /usr/src/linux-headers-$(<span class=built_in>uname</span>
                                                -r)/Module.symvers .
                                            </span>
                                            <br>
                                        </pre>
                        </table>
                    </figure>
                <h2 id=准备构建环境>
                    <a class=headerlink href=#准备构建环境 title=准备构建环境></a>
                    准备构建环境
                </h2>
                <p>
                    执行：
                    <figure class="highlight sh">
                        <table>
                            <tbody>
                                <tr>
                                    <td class=gutter>
                                        <pre>
                                            <span class=line>1</span>
                                            <br>
                                            <span class=line>2</span>
                                            <br>
                                        </pre>
                                    <td class=code>
                                        <pre>
                                            <span class=line>make oldconfig &&make prepare</span>
                                            <br>
                                            <span class=line>make modules_prepare</span>
                                            <br>
                                        </pre>
                        </table>
                    </figure>
                <p>当它们准备完成后，就可以只编译目标模块了。
                <h2 id=只编译目标模块>
                    <a class=headerlink href=#只编译目标模块 title=只编译目标模块></a>
                    只编译目标模块
                </h2>
                <p>
                    Linux 内核允许使用 <code>M=&lt;path></code>
                    的方式仅构建某个目录下的模块，这大大缩短编译时间。
                <p>
                    以 KVM 模块为例：
                    <figure class="highlight sh">
                        <table>
                            <tbody>
                                <tr>
                                    <td class=gutter>
                                        <pre>
                                            <span class=line>1</span>
                                            <br>
                                        </pre>
                                    <td class=code>
                                        <pre>
                                            <span class=line>
                                                make -j$(<span class=built_in>nproc</span>
                                                ) M=<span class=built_in>arch</span>
                                                /x86/kvm modules
                                            </span>
                                            <br>
                                        </pre>
                        </table>
                    </figure>
                <p>只会编译：
                <ul>
                    <li>
                        <code>arch/x86/kvm/kvm.ko</code>
                    <li>
                        <code>arch/x86/kvm/kvm-intel.ko</code>
                        （Intel 虚拟化支持）
                    <li>
                        <code>arch/x86/kvm/kvm-amd.ko</code>
                        （如果是 AMD）
                </ul>
                <p>
                    以 <code>kvm-intel.ko</code>
                    为例，编译完成后可以查看模块信息：
                    <figure class="highlight sh">
                        <table>
                            <tbody>
                                <tr>
                                    <td class=gutter>
                                        <pre>
                                            <span class=line>1</span>
                                            <br>
                                        </pre>
                                    <td class=code>
                                        <pre>
                                            <span class=line>
                                                modinfo <span class=built_in>arch</span>
                                                /x86/kvm/kvm-intel.ko
                                            </span>
                                            <br>
                                        </pre>
                        </table>
                    </figure>
                <p>可以确认版本号、依赖项、符号是否正确。
                <h2 id=替换内核模块>
                    <a class=headerlink href=#替换内核模块 title=替换内核模块></a>
                    替换内核模块
                </h2>
                <p>
                    为了让系统使用我们自己编译的版本，需要将它复制到系统模块目录中：
                    <figure class="highlight sh">
                        <table>
                            <tbody>
                                <tr>
                                    <td class=gutter>
                                        <pre>
                                            <span class=line>1</span>
                                            <br>
                                            <span class=line>2</span>
                                            <br>
                                        </pre>
                                    <td class=code>
                                        <pre>
                                            <span class=line>
                                                <span class=built_in>sudo</span>
                                                <span class=built_in>cp</span>
                                                <span class=built_in>arch</span>
                                                /x86/kvm/kvm-intel.ko \
                                            </span>
                                            <br>
                                            <span class=line>
                                                /lib/modules/$(<span class=built_in>uname</span>
                                                -r)/kernel/arch/x86/kvm/
                                            </span>
                                            <br>
                                        </pre>
                        </table>
                    </figure>
                <p>
                    然后更新模块依赖：
                    <figure class="highlight sh">
                        <table>
                            <tbody>
                                <tr>
                                    <td class=gutter>
                                        <pre>
                                            <span class=line>1</span>
                                            <br>
                                        </pre>
                                    <td class=code>
                                        <pre>
                                            <span class=line>
                                                <span class=built_in>sudo</span>
                                                depmod -a
                                            </span>
                                            <br>
                                        </pre>
                        </table>
                    </figure>
                <p>这样系统就能识别新的模块文件。
                <h2 id=加载模块>
                    <a class=headerlink href=#加载模块 title=加载模块></a>
                    加载模块
                </h2>
                <p>
                    卸载旧模块后再加载新的模块。若旧模块已加载，可先移除：
                    <figure class="highlight sh">
                        <table>
                            <tbody>
                                <tr>
                                    <td class=gutter>
                                        <pre>
                                            <span class=line>1</span>
                                            <br>
                                        </pre>
                                    <td class=code>
                                        <pre>
                                            <span class=line>
                                                <span class=built_in>sudo</span>
                                                modprobe -r kvm_intel
                                            </span>
                                            <br>
                                        </pre>
                        </table>
                    </figure>
                <p>
                    然后加载我们编译过的模块，并附带参数：
                    <figure class="highlight sh">
                        <table>

                                        </pre>

                                        <pre>
                                            <span class=line>
                                                <span class=built_in>sudo</span>
                                                modprobe kvm_intel pt_mode=1
                                            </span>
                                            <br>
                                        </pre>
                        </table>
                    </figure>
                <p>若加载成功，说明自定义模块已生效。
